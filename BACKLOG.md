## Personalized warm-up ramps learned from logged history (owner idea — 2026-06-21)

**NEW — owner direction.** Atlas should *always* suggest a ramp on main compounds (confirmed good), but when a user has logged history it should recognize **their** ramp pattern instead of always prescribing the generic `buildWarmupRamp` (50/70/85% @ 8/5/3, fixed 3 steps).

**Live evidence (owner history, Thu Jun 18):** Bench Press logged as `135×15 @6 → 185×10 @2 → 225×8 @1 → 225×5 @2 → 225×5 @2` — the user ramps with ~2 warm-up sets at **higher reps** than the generic ramp and **tags warm-ups with high RIR** (`@6`); accessories (Seated Row / Weighted Dip / Face Pull, all `@2` flat) get no ramp. So warm-up sets are **cleanly detectable in `Log_Cleaned`** via high RIR (reps-in-reserve ≥ ~4–5) + ascending load into a top set.

**Design (deterministic, engine-first, no LLM):**
- A pure analytics pass (`services/`) that, per lift, infers the user's ramp **shape** from history — number of warm-up sets, load steps as %-of-top-set, and rep scheme — and prescribes a ramp matching it, scaled to the current working weight and rounded to plate increments.

- Selection layered into `attachMainCompoundWarmups` (it already owns which lifts ramp): personalized shape if confident, else generic.

**Open design questions:** (a) confidence threshold — min sessions with a detectable ramp before overriding generic; (b) per-lift vs per-movement-pattern learning; (c) recency/EWMA weighting if the pattern drifts.
