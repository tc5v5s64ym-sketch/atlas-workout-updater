# Atlas — Technical & Functional Audit (2026-06-12)

Full audit of the repository: backend, parser, frontend PWA, tests, CI, docs,
dependencies, and git history. Performed by an AI agent session on branch
`claude/stoic-cannon-jiosra`; verified against the code at the cited locations.

**Snapshot note:** the audit was performed against commit `8907aa7`. `main`
advanced to `a2e91c4` during the audit (notably PR #138 backend hardening and
PR #136 e2e-in-CI); findings below were re-verified against that head and
updated where landed work resolved them. Cited `file:line` references are
from the audited snapshot and may drift slightly.

## Verdict

Atlas is in good shape for a single-owner, safety-first workout logger. The
write path is the best-engineered part of the codebase — dry-run proof fields,
idempotency tokens, duplicate guards, read-back-before-delete, and a test suite
that asserts the dangerous details (delete indices, no-write proofs, cache
bypass for safety reads). All 397 tests pass in ~0.7s. Every invariant in
`docs/INVARIANTS.md` was checked line-by-line and all hold **going forward**,
with one historical exception: `.env` was committed to the repository in the
past (see finding 0). The current working tree is clean, `.env` is no longer
tracked, and all "PRIVATE KEY" matches reachable from `main` are test stubs
and `.env.example` placeholders — but the historical commits still exist on
unmerged remote branches.

## Findings

### Critical — historical secret exposure

0. **`.env` was committed to the repository and the commits are still
   retrievable.** Commit `acb842e` ("Create .env", 2026-05-19) added a 6-line
   `.env`; `e4780c2` updated it; `ca44127` (PR #30) removed it from tracking.
   Removal from tracking does not unpublish the blobs: the commits are not
   reachable from `main`, but they remain fetchable via stale remote branches
   (the repo has ~100 unmerged `claude/*` and `codex/*` branches on GitHub).
   Per `docs/SECRET_ROTATION_RUNBOOK.md`, the file held real environment
   values; per `docs/SECRET_HYGIENE_PLAN.md`, Phase 3 (manual rotation) is an
   owner action whose completion cannot be verified from the repo, and
   Phase 4 (history cleanup) was never decided. Treat every value that was in
   that file (`ATLAS_API_KEY`, `GOOGLE_PRIVATE_KEY` / service-account
   credentials, `GOOGLE_SHEETS_ID`, `OPENAI_API_KEY`) as exposed until the
   owner confirms rotation per the runbook. Recommended: (a) owner confirms
   `docs/SECRET_HYGIENE_CHECKLIST.md` "Manual Rotation Complete" items,
   (b) delete merged/stale remote branches so the old blobs stop being
   reachable, (c) decide Phase 4 (history rewrite or GitHub support purge) —
   owner approval required. Do not print or paste the historical file
   contents anywhere while doing this.

   *Audit correction note:* the first revision of this audit wrongly stated
   `.env` was never committed. The audit ran in a clone that had fetched only
   `main` and the working branch, so `git log --all` could not see the other
   remote branches. Flagged by automated review on PR #143; confirmed against
   the GitHub API. Lesson for future audits: scan history with all remote
   refs fetched (`git fetch origin '+refs/heads/*'`) or via the hosting API.

### Bugs

1. **`/api/history/recent` returns the OLDEST effort rows, not the newest.**
   `index.js:642` uses `filteredEffort.slice(0, limit)` while log sets
   correctly use `slice(-limit)`. With default `limit=5` the field labeled
   `recent_effort` contains rows 16–20 of the last-20 window.
2. **Retry-duplication hazard in `/api/log-workout`** (`index.js:1836-1876`):
   if the log append succeeds but the effort append fails, `failWrite()`
   deletes the idempotency record, so a retry with the same `write_id`
   re-appends the log rows. Unlike `/api/complete-workout`, this endpoint has
   no composite-key (session_id+exercise+set_number) duplicate check to catch
   it.
3. **Server-side date fallback uses server-local time** (UTC on Render):
   `getLocalDateString` / `formatAmPmSuffix` at `index.js:346-401` give API
   callers that omit `date` a wrong date for evening workouts. Related:
   `public/app.js:2522` defaults the bodyweight date via `toISOString()` (UTC)
   while the rest of the UI uses local time.
4. **Session-ID collisions by design:** `generateSessionId`
   (`index.js:398-402`) always emits suffix `-01`, so a second same-half-day
   session hard-409s with manual session_id editing as the only recourse.

### Security / dependencies

5. `npm audit`: **3 moderate** advisories — `uuid` via `googleapis-common`
   ≤7.2.0 via the locked `googleapis` 121.x. Fix is a `googleapis` major bump
   (Sheets v4 surface is stable).
6. **multer is on the EOL 1.x line** (`1.4.5-lts.2`; 2025 DoS advisories).
   Upgrade to `^2.0.2` (busboy API unchanged for this usage).
7. **RESOLVED in code by PR #138** (landed on `main` during this audit):
   CORS is now an origin allowlist that defaults to deny, the API key
   comparison is timing-safe, per-scope rate limits cover `/api`, vision
   uploads, and writes, and JSON bodies are capped at 1 MB. Remaining owner
   action: set `CORS_ORIGIN` to the app origin in Render (env change —
   explicit owner approval per Invariant S4).
8. **PWA has no CSP** and several `innerHTML` sinks interpolate response
   strings (e.g. `runHealthCheck` in `public/app.js`); the API key lives in
   `localStorage`, so one injected string = key theft. Add a restrictive CSP
   meta tag and switch those renderers to `textContent`.
9. **`sheets.js` logs full row payloads and full Google API responses**
   (`sheets.js:41,59`) — workout data accumulating in Render logs. Log counts
   and ranges, not contents. (PR #138 already converted the `/api/log-workout`
   handler's logs to structured counts; `sheets.js` still logs the payloads —
   re-verified on `main@a2e91c4`.)

### Hygiene / consistency (low risk)

10. Committed artifacts to remove/relocate: `atlas-work-changes.patch` (stale
    519-line patch; scanned, no secrets) and `workout-payload.json` (sample
    write payload at repo root; move to test fixtures or delete, per the
    spirit of Invariant S1).
11. `/api/complete-workout` double-nests its envelope (`data.data`,
    `index.js:1650-1703`) vs `/api/log-workout`'s flat body; the frontend
    compensates (`public/app.js:2139`). Duplicate in-progress responses also
    return `status:'ok'` with HTTP 409.
12. Dead code: `routeRegistry`/`registerRoute` (`index.js:574-578`, used by
    only 2 of 43 routes, never read) and `would_write` at `index.js:1658`
    (always true).
13. `/api/log-workout`'s `effort_row` is shape-checked but not bounds-checked
    (`index.js:255-279`) — HR 5000 writes cleanly; `/api/complete-workout`
    validates the same metrics. Unify.
14. `/version` runs `execSync('git describe')` on every request of a public
    route (`index.js:584-597`); compute once at startup.
15. `config/routes.js` marks `/api/parse-workout-image` `writeCapable:true`
    but the handler never writes; the manifest is the trust surface — correct
    it to read-only.
16. Performance (note only, no action required yet): new `GoogleAuth` client
    per Sheets call (`sheets.js:21-33`); `getLogCompositeKeys` does 3
    sequential column reads (`sheets.js:139-157`) that could be one
    `batchGet`; analytics endpoints read full `A:Z` tabs (mitigated by the
    30s cache, fine at current scale).

### Tests, CI, docs

- Tests are a genuine strength: 397 passing across 5 files, fast, asserting
  proof fields, delete indices, idempotency replay, cache bypass, parser
  goldens. Gap: nothing covers `/api/history/recent` effort ordering — exactly
  where finding 1 lives. (The audited snapshot lacked e2e in CI; PR #136 on
  `main` has since wired the Playwright suite into the CI workflow, and
  PR #138 added `test/security.test.js`.)
- CI is well-designed: lint + tests on every PR, gated smoke tests against
  Render, daily read-only Mission Control run that auto-files a labeled issue
  on failure.
- Docs are extensive and mostly accurate, but sprawling (24 files in `docs/`
  plus 7 root markdown files) with some staleness (e.g. Railway references in
  the committed patch artifact; deployment is Render).
